## 2. 매출 상태 머신

매출은 3단계로 진행되며, 트리거 컬럼들의 OR 조건으로 상태 전이.

```
       ┌──────┐
       │ 주문 │  거래처(D) 입력만 된 상태
       └──┬───┘
          │ 납품 트리거 OR 셋 중 하나
          │  - M열 거래명세서 = "O"
          │  - P열 세금계산서 = "O"
          │  - R열 입금통장 = "사업자B" (무자료 거래의 납품 증거)
          ▼
      ┌────────┐
      │납품완료│  N열 수금예정일 ≥ 오늘
      └──┬─────┘
         │ N열 수금예정일 < 오늘                 O열 수금완료 = "O"
         ▼                                          ▼
     ┌──────┐  ──── O열 수금완료 = "O" ────► ┌────────┐
     │ 연체 │                                │수금완료│
     └──────┘                                └────────┘
```

### 핵심 통찰

- **B계좌 입금이 납품 완료 트리거 중 하나** — 무자료 거래에는 거래명세서·세금계산서가 안 나오므로, "B계좌에 돈이 들어왔다"는 사실 자체가 납품의 증거.
- **주문 단계에서는 미수금 0** — 회계상 매출 인식 X.
- **수금완료가 모든 것을 종료시킨다** — 어느 상태에서든 O=O이면 즉시 수금완료.

### 수식 (참고)

```
상태 = IF($O="O", "수금완료",
        IF(OR($M="O", $P="O", $R="사업자B"),
           IF(AND($N<>"", $N<TODAY()), "연체", "납품완료"),
           "주문"))
```

## 3. 매입 상태 머신

매출과 대칭 구조. 컬럼 이름만 다름.

```
   발주 → 입고완료 → 결제완료
              ↓ 결제예정일 지남
           결제연체
```

| 단계 | 트리거 |
|---|---|
| 발주 | 매입처(D) 입력만 |
| 입고완료 | M=O (거래명세서수취) OR P=O (세금계산서수취) OR R=사업자B |
| 결제완료 | O=O (결제완료) |
| 결제연체 | 입고완료 + N(결제예정일) < 오늘 |

## 5. 미수금 / 미지급금 계산

```
미수금 = IF(금액=0, 0,
          IF(수금완료=O, 0,
            IF(거래명세서=O OR 세금계산서=O OR 입금통장=사업자B,
               금액,
               0)))
```

즉, **납품 완료된 상태에서 수금이 안 됐을 때만** 미수금이 잡힌다. "주문" 단계는 미수금 0.

미지급금도 동일 패턴 (입고완료 + 결제 미완료).

**6월 시스템에서는 generated column으로 처리**:
```sql
outstanding_amount NUMERIC GENERATED ALWAYS AS (
  CASE
    WHEN amount IS NULL OR amount = 0 THEN 0
    WHEN payment_received THEN 0
    WHEN delivery_note OR tax_invoice OR account_in = 'B'
      THEN amount
    ELSE 0
  END
) STORED
```

## 6. 미수 등급 분류

미수일수 = `TODAY() - 수금예정일`

| 등급 | 미수일수 | 색상 | 액션 |
|---|---|---|---|
| **정상** | ≤ 0 (예정일 미도래) | 녹색 | — |
| **단기 연체** | 1~7일 | 노랑 | 본인에게 알림 |

| **장기 연체** | 31일 이상 | 빨강 | 본인+친구 알림, 신용 모니터링 강화 |

거래처별 "최악 등급"은 그 거래처의 미수 건들 중 가장 심각한 등급으로 표시.

## 8. 통장 누적잔고 계산

같은 통장 코드(`6.통장.C열`) 안에서만 위쪽 행의 입금/출금을 누적.

```
G2 = SUMIFS($E$2:E2, $C$2:C2, C2) - SUMIFS($F$2:F2, $C$2:C2, C2)
```

시작잔고는 워크북 행 2~4에 입력 (법인A / 사업자A / 사업자B).

**6월 시스템에서는**: `bank_transactions` row 단위 + materialized view로 잔고 계산. 또는 `bank_balance_snapshots` 일별 스냅샷.

## 11. 정기업무 주기

| 주기 | 다음 실행일 자동 계산 |
|---|---|
| 매일 | +1일 |
| 매주 | +7일 |
| 매월 / 매월 N일 | 다음 달 같은 날 (1일이면 다음 달 1일) |
| 매분기 | +3개월 |
| 매2개월 / 매3개월 / 매6개월 | +N개월 |
| 매년 / 매년 N월 | 다음 해 같은 날 (월 지정 시 다음 해 그 월의 같은 날) |
| 일회성 | 다음 실행일 = 현재 실행일 (완료되면 더 이상 알림 X) |

**현재 워크북 한계**: 다음 실행일 자동 갱신 안 됨 (수동). 시스템에서는 cron-like 자동 계산.

## 12. 한국 세무 컨텍스트 (요약)

### 부가세 신고
- 분기별 신고 (4/25, 7/25, 10/25, 1/25)
- 일반과세자: 매출 - 매입의 부가세 차액 납부
- B계좌 거래는 매출에서 제외 → **친구 개인사업자에서만 발생, 법인 절대 X**

### 의제매입세액공제
- 면세 농수산물 매입 시 부가세 공제 가능
- 철강 유통에는 거의 무관 — 단, 폴리싱 작업 시 면세 자재 사용 가능성 검토 필요

### 특수관계자 거래
- 법인과 친구 사업자 사이 거래는 시세 기반 필수
- 부당행위 판정 시 추징 위험
- 한 거래처 비중 70% 이하 유지 룰

### 가공 세금계산서 절대 금지
- 실거래 없는 세금계산서 발행 → 조세범처벌법 (3년 이하 징역)
- 친구가 과거에 했더라도 동업 시작 후에는 0%

## 4. 9.영업내역 시트 설계 + 추가 (commit `01df1da`)

### 4-1. 설계 갈래

**(A) 활동 단위 (이벤트 로그형)** — 한 행 = 한 번의 활동 (전화/방문/견적/카톡)
**(B) 리드 단위 (파이프라인형)** — 한 행 = 한 영업 기회. 단계 컬럼만 갱신

**선택: (A) 활동 단위.** 이유:
- 워크북 현재 패턴(`1.매출`/`2.매입` = 거래 이벤트)과 일관
- 시스템에서 이벤트 로그 → 파이프라인 view는 group by/window로 파생 가능, 그 반대는 어려움
- 활동 이력 보존 필요 (6월 시스템에서 거래처별 활동 timeline 구성)

### 4-2. 핵심 결정: 5.거래처 마스터 매칭 강제 X

사용자 인사이트:
> "지나가다 공사하는데 있음 명함을 준다던가 하는것도 모두 영업활동에 해당"

→ 콜드 prospecting 입력 시 거래처 마스터 미등록이 정상. 매칭 강제하면 입력 자체를 막게 됨.

**해법**:
- `거래처/잠재처` 컬럼 = 자유 텍스트
- `등록여부` 컬럼 = 자동 수식 `IF(COUNTIF('5.거래처'!B:B, C)>0, "등록", "잠재")`
- 잠재처는 옅은 파랑 강조 (시각적 구분)
- CLAUDE.md 절대 룰 #3 scope 명확화: "매출/매입에만 적용, 영업내역은 예외"

### 4-3. 시트 컬럼 (15개)

| # | 컬럼 | 자동/수동 | 비고 |
|---|---|---|---|
| A | 일자 | 수동 | DATE |
| B | 활동ID | **자동** | YYYYMMDD-NNN |
| C | 거래처/잠재처 | 수동 | 자유 텍스트 |

| H~K | 품목/규격/예상수량/예상금액 | 수동 | optional |
| L | 결과 | 수동 | 진행중/수주/실주/보류 |

**활동유형**: 전화/방문/견적/카톡/문자/**명함전달**/**명함수령**/**현장콜드**/기타

### 4-4. 조건부 서식

- 결과별 색상: 진행중=노랑, 수주=녹색(행 전체), 실주=회색, 보류=옅은 주황
- 등록여부="잠재" → 옅은 파랑 (콜드 prospecting 시각화)
- 다음 follow-up overdue (`AND(L="진행중", N<>"", N<TODAY())`) → 빨강

### 4-5. 6월 시스템 매핑

```
9.영업내역 → sales_activities 테이블
  + parties.kind ENUM에 'PROSPECT' 추가
  + 워크북 자유텍스트 잠재처 → 마이그레이션 시 parties(kind=PROSPECT)로 dedup INSERT
  + 거래 발생 시 PROSPECT → CUSTOMER로 promote
  + 등록여부 컬럼은 시스템에서 제거 (parties.kind로 흡수)
  + 매출ID (text) → sale_id (UUID FK)
```

새 enum: `activity_kind` (9종), `activity_outcome` (4종).
새 view: `party_pipeline` (거래처별 진행중/수주/실주 카운트 + 다음 follow-up).

## 2026-05-06 — [feature] 사업자 차원 3분할: 법인/사업자/B계좌

**변경 이유**:
- 무자료 거래(B통장)를 사업자 차원에서 명시적으로 식별 필요. 기존엔 `입금통장=사업자B`로만 표시돼 SUMIFS·신고 분리에 누락 위험.
- "B계좌"를 사업자 옵션으로 추가하면 부가세 신고 합계(법인+사업자) 자동 분리 → CLAUDE.md 절대 룰 #2(B계좌 시각·권한 분리) 자동 충족.

**영향**:
- 1.매출 K열 드롭다운: `법인,사업자` → `법인,사업자,B계좌`
- 2.매입 K열 드롭다운: 동일
- 5.거래처 I열(선호사업자) 드롭다운: 동일
- 현황판: A8/B8 "B계좌 (히든) 매출", D8/E8 "B계좌 (히든) 매입" 행 추가. 기존 B7/E7 라벨을 "합계"→"신고 합계"로 명시. 영업이익(B10=B7-E7)은 신고 기준 그대로.
- 샘플 데이터: 김씨건축(매출), 개인 김씨(매입) K값 `사업자→B계좌`. 5.거래처 동일 거래처 I값도 `사업자→B계좌`.
- 3.재고 D열, 6.통장 B열은 변경 없음 (B계좌는 entity가 아닌 통장 차원이라 재고/통장 컨텍스트엔 부적합).

**migrate.py 갱신**: 없음 (컬럼 위치/개수/수식컬럼 모두 동일)
**관련 commit**: 978ec37

## 2026-05-06 — [breaking] 통장 코드 통일: 사업자B → B계좌

**변경 이유**:
- 사업자 차원에 "B계좌"를 추가했는데 통장 코드는 여전히 "사업자B" — 명명 불일치로 사용자 혼동.
- "사업자B"라는 이름이 entity인지 통장 코드인지 모호. "B계좌"로 통일하면 통장 차원이 명확 (법인A/사업자A/B계좌/현금).

**영향**:
- 1.매출 R열, 2.매입 R열, 6.통장 C열 드롭다운: `사업자B` → `B계좌`
- 매출/매입 상태 머신 수식: `R="사업자B"` 분기 → `R="B계좌"`
- 매출/매입 R열 조건부 서식: 동일
- 6.통장 C열 조건부 서식, 잔고 요약 영역(L열), 누적잔고 계산 보조 라벨: 동일
- 현황판 통장별 잔고 라벨/SUMIFS: `사업자B` → `B계좌`
- 샘플 데이터 + data/2.매입.csv, data/6.통장.csv 값 변경
- CLAUDE.md, docs/도메인_룰.md, docs/시스템_DB_스키마_v0.md 명명 갱신

**자동 통장 추가는 6월 시스템 작업으로**: 매출 (금액+수금완료=O+입금통장) 충족 시 6.통장 자동 행 추가는 Excel 한계로 5월 미구현. 0.개선아이디어 시트에 6월 백로그 등록.

**migrate.py 갱신**: 없음 (컬럼 구조 동일)
